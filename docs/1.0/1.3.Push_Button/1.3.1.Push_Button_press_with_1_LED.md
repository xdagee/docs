## 1. The Call to Adventure

Computers are smart, but sometimes they need human input. The **Push Button** is the simplest way for a person to talk to a machine.
Your mission is to build a "Doorbell" circuit where the input determines the output state.

## 2. The Toolkit

* **1x Push Button** (The Input)
* **1x LED** (The Output)
* **1x Arduino Uno**
* **3x Jumper Wires**
* **1x Breadboard**

## 3. The Blueprint

**Caution:** Buttons have 4 legs. Use **2 diagonal legs** to ensure the connection works correctly.

* **Button Pin A** -> **Pin 2**
* **Button Pin B** -> **GND**
* **LED (+) Long Leg** -> **Pin 6**
* **LED (-) Short Leg** -> **GND**

![Push Button Circuit](../../assets/1.0/Push_Button/Push_Button_One_LED/Push_Button_Fig.7.webp)

## 4. The Logic

We use `INPUT_PULLUP` mode, which uses "Inverse Logic".

* **Default (Not Pressed)** = 5V (HIGH)
* **Pressed (Connected to GND)** = 0V (LOW)

### The Code

```cpp
// Mission 1.13: The Manual Trigger
const int buttonPin = 2;
const int ledPin = 6;

void setup() {
  pinMode(ledPin, OUTPUT);
  // INPUT_PULLUP enables the internal brain resistor
  pinMode(buttonPin, INPUT_PULLUP);
}

void loop() {
  // Read the button state
  int isPressed = digitalRead(buttonPin);

  if (isPressed == LOW) { // LOW means the button is pressed!
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }
}
```

## 5. Upload & Test

1. Upload the code.
2. Press the button. Does the light shine?
3. **Upgrade**: Can you add a second LED that turns on when the button is NOT pressed?

## 6. Troubleshooting

* **LED stays ON when released?** Check your code logic: `LOW` means pressed, `HIGH` means released.
* **Nothing happens?** Ensure the button is snapped firmly across the "middle trench" of the breadboard.
